# Программный комплекс для сбора и анализа вакансий с hh.ru

## 1. Общее описание

Программный комплекс разработан в рамках выполнения курсовой работы по дисциплине «Проект (практикум) по экономической социологии» на тему «Практики российских IT-компаний по привлечению, адаптации и удержанию сотрудников поколения Z». Комплекс предназначен для автоматизированного сбора и предварительной обработки данных о вакансиях уровня «Junior» и «Стажер» с портала hh.ru.

Комплекс реализует первый этап исследовательской методологии — количественный анализ декларируемых условий труда в IT-вакансиях, ориентированных на привлечение молодых специалистов (поколения Z). Полученные данные служат эмпирической базой для последующего качественного этапа, включающего интервью с HR-специалистами и тим-лидерами.

## 2. Функциональное назначение

Программный комплекс решает следующую исследовательскую задачу: выявление декларируемых в IT-вакансиях условий трудоустройства, направленных на привлечение молодежи (количественный этап; парсинг и контент-анализ).

**Основные функции:**

1. **Автоматизированный сбор данных через API hh.ru**
   - Получение вакансий по идентификаторам компаний
   - Параметризация запросов (количество вакансий на странице, пагинация)
   - Соблюдение ограничений публичного API

2. **Фильтрация вакансий**
   - Отбор позиций, релевантных для начинающих специалистов
   - Исключение ложных срабатываний с помощью контекстуальных регулярных выражений

3. **Структурирование и нормализация данных**
   - Преобразование вложенных JSON-структур в плоскую табличную форму
   - Обработка полей различных типов (словари, списки, строковые значения)
   - Форматирование числовых данных (зарплата с разделителями разрядов)
   - Дедупликация на основе уникальных идентификаторов вакансий

4. **Экспорт данных**
   - Сохранение промежуточных данных в JSON для верификации
   - Экспорт финальных результатов в CSV для статистического анализа
   - Поддержка кодировки UTF-8 для корректного отображения кириллицы

## 3. Техническая архитектура

Система построена по двухуровневой архитектуре.

**Уровень 1: Сбор данных (Bash-скрипт `hh.sh`)**

Используемые утилиты:
- `curl` — выполнение HTTP-запросов к API hh.ru
- `jq` — обработка и фильтрация JSON-данных
- регулярные выражения — лингвистический анализ названий вакансий

**Уровень 2: Обработка данных (Jupyter Notebook `parser.ipynb`)**

Используемые библиотеки Python:
- `pandas` — работа с табличными данными и экспорт в CSV
- `BeautifulSoup` — очистка HTML-содержимого вакансий
- `requests` — загрузка страниц вакансий
- `json` — чтение JSON-файлов
- `re` — регулярные выражения для текстовой обработки
- `collections.Counter` — частотный анализ фраз

## 4. Критерии отбора вакансий

Отбор осуществляется по двум критериям.

**Формальный критерий:** наличие флага `internship: true` в данных API, указывающего на официальную программу стажировки.

**Лексический критерий:** наличие в названии вакансии ключевых терминов, обозначающих начальный уровень позиции:
- «стажер» и производные («стажировка»)
- «junior» / «джуниор»
- «trainee»
- «intern»

Для исключения ложных срабатываний используется контекстуальное регулярное выражение, учитывающее границы слов: `(^|[^а-яА-Яa-zA-Z0-9])(стажер|стажёр|стажировка|junior|джуниор|trainee|intern|internship)([^а-яА-Яa-zA-Z0-9]|$)`

## 5. Методологические особенности реализации

**5.1. Обработка разнородных данных API**

API hh.ru возвращает данные в сложно структурированном формате, где одни и те же поля могут содержать данные различных типов (словарь, список словарей, строковое значение). Функция `get_field_value` реализует логику распаковки этих структур: из словаря извлекается значение по ключу `name`, из списка словарей формируется строка с перечислением названий через запятую.

**5.2. Очистка текста вакансий**

Для выделения значимого содержания из HTML-страниц реализована функция `extract_russian_text`, выполняющая следующие операции:
- удаление служебных тегов (`script`, `style`, `noscript`, `meta`, `link`, `header`, `footer`, `nav`)
- фильтрация строк длиной менее 30 символов
- проверка наличия кириллических символов
- удаление шумовых фраз (cookie, уведомления, сервисные сообщения, копирайты и пр.)

**5.3. Удаление общих фраз**

Фразы, встречающиеся более чем в 30% вакансий, считаются общими (например, стандартные блоки с условиями работы, логотипы, призывы подписаться). Они удаляются из текстов, чтобы не искажать последующий контент-анализ.

**5.4. Дедупликация**

В процессе сбора возможны случаи повторного получения одной и той же вакансии. Для обеспечения чистоты данных используется множество `seen_ids`, обеспечивающее проверку уникальности идентификатора за константное время.

**5.5. Поддержка кириллицы**

Все компоненты системы настроены на кодировку UTF-8: Bash-скрипт, чтение и запись JSON/CSV в Python, регулярные выражения.

## 6. Использование в исследовательском процессе

Комплекс является первым этапом в смешанном последовательном дизайне исследования. Финальный CSV-файл содержит следующие поля:

| Поле | Описание |
|------|----------|
| ID | Уникальный идентификатор вакансии |
| Название | Название вакансии |
| Департамент | Подразделение компании-работодателя |
| Город | Локация работы |
| Опыт | Требуемый опыт работы |
| Расписание | Тип занятости |
| Формат работы | Удаленность (гибрид, офис, удаленка) |
| Рабочие часы | Продолжительность рабочего дня |
| График | График работы (5/2, сменный и пр.) |
| Зарплата | Диапазон или условие оплаты |
| Дата публикации | Время размещения вакансии |
| Ссылка | URL вакансии |
| Текст | Очищенное описание вакансии |
| ID компании | Идентификатор работодателя |

## 7. Ограничения

**7.1. Технические ограничения**

- API hh.ru ограничивает максимальное количество вакансий в одном запросе до 100
- Скрипт сбора ограничен 20 страницами результатов (параметр `PAGES` может быть изменен)
- Установлена пауза 0.5 секунды между запросами для соблюдения этики использования API
- Структура ответов API может измениться, что потребует адаптации кода

**7.2. Методологические ограничения**

- Анализируются только декларируемые условия, которые могут расходиться с фактическими практиками найма и труда
- Лексический отбор по названиям вакансий может давать как ложноположительные, так и ложноотрицательные срабатывания
- Выборка ограничена компаниями, заданными в массиве `COMPANY_IDS`

## 8. Инструкция по запуску

1. Убедиться, что установлены необходимые утилиты: `curl`, `jq`, `python3` с библиотеками из секции 3.
2. Выполнить сбор данных:
   ```bash
   chmod +x hh.sh
   ./hh.sh
   ```
3. Открыть `parser.ipynb` в Jupyter Notebook или Jupyter Lab и выполнить все ячейки последовательно.
4. Результат сохраняется в файл `vacancies.csv` в рабочей директории.
