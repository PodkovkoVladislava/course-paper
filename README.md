# Программный комплекс для сбора и анализа вакансий с hh.ru

## Общее описание

Настоящий программный комплекс разработан в рамках выполнения курсовой работы по дисциплине «Проект (практикум) по экономической социологии» на тему «Практики российских IT-компаний по привлечению, адаптации и удержанию сотрудников поколения Z». Комплекс представляет собой специализированный инструментарий для автоматизированного сбора и первичной обработки данных о вакансиях начального уровня ("Junior" и "Стажер") с публичного портала hh.ru. Его реализация соответствует первому, количественному, этапу исследовательской методологии, цель которого — выявить спектр адаптационных практик, ориентированных на поколение Z, которые декларируются IT-компаниями на рынке труда. Полученные данные служат фундаментальной эмпирической базой для последующего качественного этапа исследования, включающего интервью с представителями HR-отделов и руководства компаний.

## Функциональное назначение программного комплекса

Комплекс решает конкретную исследовательскую задачу по выявлению декларируемых в IT-вакансиях условий трудоустройства для привлечения молодежи. В результате работы программного обеспечения был сформирован структурированный датасет, содержащий 699 уникальных вакансий от 102 ведущих IT-компаний России. Для достижения этого результата система выполняет полный цикл обработки данных: от автоматизированного сбора через API hh.ru с использованием параметризованных HTTP-запросов до интеллектуальной фильтрации, нормализации сложных структур данных и финального экспорта в форматы, пригодные для статистического анализа.

Для реализации этой задачи система выполняет следующие функции:

### 1. Автоматизированный сбор данных через API hh.ru
- Получение информации о вакансиях конкретной компании по ее идентификатору (https://api.hh.ru/vacancies?employer_id=$COMPANY_ID&per_page=$PER_PAGE&page=$i, где $COMPANY_ID отвечает за id компании)
- Параметризация запросов(количество вакансий на странице, фильтрация) (https://api.hh.ru/vacancies?employer_id=$COMPANY_ID&per_page=$PER_PAGE&page=$i, где $PER_PAGE и $i отвечают за количество вакансий на странице и страницу)
- Обработка HTTP-запросов с учетом ограничений API (максимум 2000 вакансий за запрос)

### 2. Интеллектуальная фильтрация вакансий
- Выделение позиций, релевантных для начинающих специалистов (стажеров, джуниоров) (по флагу internship == true)
- Исключение ложных срабатываний через использование контекстуальных регулярных выражений (по условию наличия в названии вакансии стажер|стажёр|стажировка|junior|джуниор|trainee|intern|internship|младший)

### 3. Структурирование и нормализация данных
- Преобразование сложных JSON-структур в плоскую табличную форму
- Обработка разнотипных данных (словари, списки, простые значения)
- Устранение дубликатов на основе уникальных идентификаторов вакансий

### 4. Экспорт в аналитически удобные форматы
- Сохранение промежуточных данных в JSON для верификации
- Экспорт финальных результатов в CSV для последующего статистического анализа
- Поддержка кириллической кодировки для корректного отображения русскоязычного контента

## Техническая архитектура

Архитектура системы построена по двухуровневому принципу, что обеспечивает четкое разделение ответственности и гибкость. Первый уровень, реализованный на Bash, отвечает за непосредственное взаимодействие с API hh.ru. Он использует утилиты curl для выполнения запросов и jq для потоковой обработки и фильтрации JSON-данных. Второй уровень, реализованный на Python с использованием библиотеки pandas, выполняет задачи структурирования, глубокой нормализации и очистки данных. Ключевой методологической особенностью является двухкритериальная система фильтрации вакансий, сочетающая формальный признак (наличие флага internship: true) и лингвистический анализ названий с помощью контекстуальных регулярных выражений, что минимизирует количество ложных срабатываний.

**Уровень 1: Сбор данных (Bash-скрипт)**
Использует стандартные утилиты командной строки:
- `curl` для выполнения HTTP-запросов к API hh.ru
- `jq` для обработки и фильтрации JSON-данных
- Регулярные выражения для лингвистического анализа названий вакансий

## Критерии отбора вакансий

Отбор релевантных для исследования вакансий осуществляется по строго заданным критериям. Формальным основанием для включения является наличие в ответе API специального флага, указывающего на программу стажировки. Лексическим основанием служит наличие в названии вакансии одного из ключевых терминов. Для обеспечения точности отбора регулярное выражение настроено на учет границ слов, что позволяет исключить из выборки позиции, в названиях которых эти термины употреблены в ином контексте (например, "Senior").

1. **Формальный критерий**: наличие флага `internship: true` в данных API, указывающего на официальную программу стажировки.

2. **Лексический критерий**: наличие в названии вакансии ключевых терминов, обозначающих начальный уровень позиции:
   - "стажер" и "стажёр"
   - "стажировка" 
   - "junior" 
   - "джуниор"
   - "trainee"
   - "intern"
   - "internship"
   - "младший"

Для исключения ложных срабатываний используется контекстуальное регулярное выражение, учитывающее границы слов.

## Методологические особенности реализации

### Обработка разнородных данных API
Работа с API hh.ru сопряжена с обработкой сложных, неоднородных JSON-структур, где одни и те же поля могут содержать данные разных типов. Для устойчивого извлечения информации реализована рекурсивная логика в вспомогательной функции get_field_value. Важным аспектом обеспечения качества финального датасета является механизм устранения дубликатов на основе уникальных идентификаторов вакансий, что гарантирует чистоту данных для последующего контент-анализа. Все компоненты системы настроены на полную поддержку кириллицы, включая указание корректной кодировки при чтении и записи файлов, что является обязательным условием для работы с русскоязычным контентом.

### Устранение дубликатов
В процессе сбора данных возможны случаи дублирования вакансий. Для обеспечения чистоты данных для последующего статистического анализа реализован механизм отслеживания уникальных идентификаторов вакансий через множество `seen_ids`, что обеспечивает константную сложность проверки на дублирование.

### Поддержка кириллицы
Учитывая, что анализ ведется на русскоязычных данных, все компоненты системы настроены на корректную обработку кириллицы:
- Bash-скрипт использует UTF-8 кодировку
- Python-скрипт указывает кодировку `utf-8` при экспорте CSV
- Регулярные выражения поддерживают как кириллические, так и латинские символы

## Инструкция по развертыванию и использованию

Для запуска программного комплекса необходимо наличие базовых инструментов командной строки: curl и jq. Установка Python-зависимостей, указанных в файле requirements.txt, выполняется стандартными средствами. Полный цикл работы системы инициируется последовательным выполнением двух скриптов. Первый скрипт, hh.sh, осуществляет сбор сырых данных с API и сохраняет их в файл vacancies.json. Второй скрипт, parser.ipynb, загружает этот файл, выполняет нормализацию, очистку от дубликатов и экспортирует итоговый датасет в файл vacancies.csv в формате, готовом для импорта в статистические пакеты или электронные таблицы. Далее этот блокнот будет дополнен интеллектуальной обработкой данных для вычленения остальных признаков ml-инструментами.

## Использование в исследовательском процессе

Данный программный комплекс является первым этапом в смешанном последовательном дизайне исследования. Полученные данные (CSV-файл с вакансиями) служат:

1. **Эмпирической базой** для контент-анализа декларируемых HR-практик
2. **Основой для триангуляции** — сравнения декларируемых условий с фактически реализуемыми практиками

## Ограничения

Работа комплекса имеет ряд технических и методологических ограничений. К техническим относятся лимиты, накладываемые публичным API hh.ru на объем и частоту запросов, а также зависимость логики парсинга от текущей структуры ответов API, которая может изменяться. Методологическое ограничение заключается в том, что анализ проводится исключительно на основе декларируемых в вакансиях условий, которые могут отличаться от фактических практик внутри компаний. Перспективами развития системы могут стать расширение лингвистического анализа на тексты описаний вакансий, реализация механизмов для регулярного мониторинга и сравнения данных, а также интеграция с другими платформами по поиску работы для проведения сравнительных исследований.
